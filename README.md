# Умный подбор event-подрядчиков

Сервис помогает заказчику выбрать до трёх подрядчиков из каталога своего города. Он учитывает дату, формат, категорию и бюджет, а при наличии — длительность, язык и текстовое пожелание. Каждая карточка объясняет выбор проверяемыми фактами и фрагментом исходного описания. Проект подготовлен для задачи Firebird на HackAlem AI.

## Что реализовано

- `POST /recommendations` на FastAPI и команда `python -m contractor_match recommend` с общей логикой.
- `GET /catalogue/options` возвращает города, категории по городам, доступные форматы и языки, а также границы календаря. Названия города, категории, формата и языка принимаются независимо от регистра.
- Три исхода: `matched`, `category_absent`, `no_eligible`. Пустой результат всегда сопровождается понятным сообщением.
- Исключение занятых на дату, неподходящих по формату, стартовой цене, языку и длительности. Площадки обрабатываются так же, как остальные категории.
- Воспроизводимый порядок: локальный TF-IDF по символьным n-граммам описаний, затем стартовая цена и `id` при равенстве. AI не переставляет карточки.
- Один AI-вызов на весь набор выбранных карточек для поиска подтверждающих цитат. Работают OpenAI и NVIDIA; без ключа, при ошибке, неподтверждённой цитате или тайм-ауте используется локальный запасной режим.
- Сохранены признаки `synthetic`, `city_imputed`, `price_imputed` исходного датасета. Дополнительные профили не создавались.

## Установка и запуск

Нужен Python 3.11 или новее. Из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn contractor_match.api:app --host 127.0.0.1 --port 8000
```

На Linux или macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`. Документация API появится по адресу `http://127.0.0.1:8000/docs`; проверка сервиса — `GET /health`.

### AI-провайдер

По умолчанию `AI_PROVIDER=auto`: при наличии ключа выбирается OpenAI, иначе NVIDIA. Если ключей нет или вызов не прошёл за 6 секунд, объяснения создаются локально. Для NVIDIA Build `mistralai/mistral-nemotron` задайте ключ `nvapi-…` через переменную окружения, например в PowerShell:

```powershell
$env:NVIDIA_API_KEY = '<ваш ключ nvapi-…>'
```

Для OpenAI:

```powershell
$env:AI_PROVIDER = 'openai'
$env:OPENAI_API_KEY = '<ваш ключ>'
```

Список переменных есть в `.env.example`. Файл служит образцом; приложение читает **переменные окружения**, а не `.env`. Не добавляйте реальные ключи в репозиторий. Для проверки запасного режима без сети задайте `AI_PROVIDER=local` либо не задавайте ключ. В ответе поле `ai_mode` показывает `openai`, `nvidia`, `fallback` либо `not_used`, когда карточек нет.

Ключи NVIDIA Brev (`bak-…`) и идентификаторы организации (`org-…`) не подходят для `NVIDIA_API_KEY`: они относятся к управлению ресурсами Brev. Для используемого здесь endpoint NVIDIA Build нужен отдельный ключ `nvapi-…`, созданный в [настройках Build](https://build.nvidia.com/settings/api-keys). См. [разделение ключей в документации Brev](https://docs.nvidia.com/brev/guides/api-keys).

OpenAI вызывается через [Responses API со структурированным выводом](https://developers.openai.com/api/docs/guides/structured-outputs), NVIDIA — через [совместимый Chat Completions endpoint](https://build.nvidia.com/mistralai/mistral-nemotron). Модели можно заменить переменными `OPENAI_MODEL` и `NVIDIA_MODEL`.

## Контракт

`POST /recommendations` принимает JSON:

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "event_format": "корпоратив",
  "category": "Ведущий",
  "budget_kzt": 1200000,
  "duration_hours": 6,
  "language": "русский",
  "brief": "спокойный ведущий делового форума"
}
```

Последние три поля необязательны. Допустимы форматы `свадьба`, `той`, `корпоратив`, `конференция`, `юбилей`, `день рождения`; языки `русский`, `казахский`, `английский`. Дата должна лежать между 23.09.2026 и 31.12.2026: вне этого окна данных о занятости нет. Неизвестный город, некорректный формат, бюджет или дата дают HTTP 422 с пояснением.

Ответ содержит `status`, `message`, до трёх `cards`, счётчики `reasons` и `ai_mode`. В карточке есть `id`, имя, категория, город, `price_from_kzt`, признаки происхождения данных, объяснение и `evidence_quote`. Счётчики причин **могут пересекаться**: один профиль бывает одновременно занят и дороже бюджета. Цена в датасете указана «от»; фактическая стоимость требует уточнения у подрядчика.

## CLI и воспроизводимая проверка

```powershell
.\.venv\Scripts\python.exe -m contractor_match recommend --city Алматы --date 2026-10-15 --event-format корпоратив --category Ведущий --budget-kzt 1200000 --brief 'спокойный ведущий делового форума'
```

Та же команда с `--json` выводит ответ в формате API. Для демонстрации последовательно измените только дату на `2026-12-19`: из шести доступных по условиям ведущих на 15 октября до одного на 19 декабря. В декабрьском ответе указано, сколько профилей занято.

Остальные сценарии:

```powershell
# Редкая категория: один подходящий
.\.venv\Scripts\python.exe -m contractor_match recommend --city Алматы --date 2026-10-15 --event-format корпоратив --category Флорист --budget-kzt 300000

# Категории нет в городе
.\.venv\Scripts\python.exe -m contractor_match recommend --city Астана --date 2026-10-15 --event-format корпоратив --category Декоратор --budget-kzt 500000

# Категория есть, но профиль занят и его цена выше бюджета
.\.venv\Scripts\python.exe -m contractor_match recommend --city Астана --date 2026-10-15 --event-format корпоратив --category Флорист --budget-kzt 100000
```

Вызов API из PowerShell:

```powershell
$body = @{city='Алматы'; date='2026-10-15'; event_format='корпоратив'; category='Ведущий'; budget_kzt=1200000} | ConvertTo-Json
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/recommendations' -Method Post -ContentType 'application/json; charset=utf-8' -Body $body
```

Тесты:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Как работает подбор

1. CSV загружается один раз; многозначные поля и даты преобразуются в наборы. Схема, число профилей и уникальность `id` проверяются.
2. Для города и категории применяются обязательные фильтры. `max_hours = null` означает, что работа не привязана к присутствию и ограничение длительности не применяется.
3. Оставшиеся профили сортируются по сходству описания с форматом и пожеланием. При равном сходстве сначала идёт меньшая стартовая цена, затем `id`. Повторный запрос даёт тот же порядок без зависимости от AI.
4. AI получает только запрос и заранее выделенные дословные фрагменты описаний выбранных профилей и выбирает по одному для каждого `id`. Каждый фрагмент проверяется по CSV; объяснение собирается из этого фрагмента и проверенных полей. Если проверка или API-вызов не удались, фрагмент выбирает локальный алгоритм. На AI-вызов установлен тайм-аут 6 секунд.

Данные: приложенный анонимизированный CSV HackAlem AI, 66 профилей. Встроены 13 синтетических профилей исходного датасета. Бронирование, заявки и актуализация календаря не реализованы; доступность отражает только календарь датасета. Ранжирование по TF-IDF учитывает буквенное сходство, а не все смысловые синонимы; AI улучшает подбор доказательства для объяснения, но не изменяет порядок.
