# Подключение фронтенда Firebird

Это инструкция для разработчика интерфейса и его Codex. Дизайн и выбранный стек остаются у команды; backend уже работает. Начните с `AGENTS.md`, затем используйте файлы ниже.

## Где что находится

| Задача | Файл / источник |
|---|---|
| Полная схема API | `integration/openapi.json`, у работающего сервера `/openapi.json` |
| Типы TypeScript | `integration/api-types.d.ts` — генерация из той же схемы |
| Готовый HTTP-клиент | `integration/api-client.mjs`, объявления `api-client.d.mts` |
| Примеры для вёрстки и тестов | `integration/examples/` — реальные ответы local + tfidf |
| Нормальные/пустые состояния | matched, short_with_alternative, category_absent, no_eligible |
| Пожелания и ошибка формы | brief_understanding, invalid_request |
| Кто вычисляет результат | `contractor_match/service.py`, не браузер |

Снимки не содержат времени выполнения и не зависят от ключей. Для визуальных моков используйте их явно как тестовые данные. Рабочая форма обращается к API.

## 1. Поднять backend

Из корня репозитория, PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
$env:AI_PROVIDER = 'local'
$env:RANKING_PROVIDER = 'tfidf'
$env:CORS_ALLOWED_ORIGINS = 'http://localhost:5173,http://127.0.0.1:5173'
.\.venv\Scripts\python.exe -m uvicorn contractor_match.api:app --host 127.0.0.1 --port 8000 --no-access-log
```

Linux / macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
AI_PROVIDER=local RANKING_PROVIDER=tfidf CORS_ALLOWED_ORIGINS=http://localhost:5173 \
  .venv/bin/python -m uvicorn contractor_match.api:app --host 127.0.0.1 --port 8000 --no-access-log
```

Если окружение уже использует эти версии, повторять установку не нужно. Зафиксированные зависимости помогают воспроизвести OpenAPI и типы. Документация: `http://127.0.0.1:8000/docs`.

## 2. Соединить приложения

**Два локальных сервера:** frontend обращается к `http://127.0.0.1:8000`. В CORS_ALLOWED_ORIGINS укажите точный origin страницы фронтенда. По умолчанию разрешены localhost и 127.0.0.1 на портах 3000, 4317, 5173. Порт и hostname имеют значение; `localhost` и `127.0.0.1` — разные origins. Настройка читается при создании приложения, после изменения перезапустите backend. Пустая строка отключает cross-origin доступ, `*` запрещён.

**Один домен / dev proxy:** передайте клиенту `baseUrl: '/api'`. Прокси должен направлять `/api/recommendations` на backend `/recommendations`, удаляя префикс `/api`. Сам backend этот префикс не добавляет. Путь `/health` также можно проксировать. Для прямого same-origin API без префикса используйте `baseUrl: ''`.

Клиент не зависит от Vite/React/Next.js. Если конфигурация проекта использует VITE_API_BASE_URL или NEXT_PUBLIC_API_BASE_URL, в ней допустим только публичный адрес. OPENAI_API_KEY, NVIDIA_API_KEY и NIM-ключи всегда серверные. `.env` backend не читает автоматически. CORS — браузерное разрешение, не аутентификация; текущий сервис предназначен для локального/контролируемого демо. Для публичного платного AI нужны отдельные ограничения доступа и расходов.

## 3. Использовать клиент

Путь импорта адаптируйте к размещению вашего frontend. В браузере без bundler папка integration должна быть доступна HTTP-серверу; открывать HTML через file:// не нужно.

```javascript
import {
  createApiClient, buildRecommendationRequest, createLatestRecommender,
} from '../integration/api-client.mjs';

const api = createApiClient({baseUrl: 'http://127.0.0.1:8000'});
const latest = createLatestRecommender(api); // один экземпляр на форму
const options = await api.catalogueOptions();

const request = buildRecommendationRequest({
  city: 'Алматы', category: 'Ведущий', date: '2026-12-19',
  event_format: 'корпоратив', budget_kzt: '1200000',
  duration_hours: '', language: '',
  brief: 'Нужен спокойный ведущий, без конкурсов, на русском',
});
const response = await latest.recommend(request);
if (response !== null) {
  // render(response): порядок response.cards сохраняется.
}

// При удалении компонента:
// latest.cancel();
```

`null` означает устаревший или отменённый через latest.cancel результат; его не отображают. Для spinner также используйте номер последней отправки, чтобы finally старого запроса не выключил загрузку нового. Прямые api.recommend/options/health принимают `{signal}`. Тайм-аут клиента — 10 секунд, включая чтение JSON; backend отводит внешним моделям общий срок 6 секунд. Отмена в браузере не гарантирует отмену уже начавшегося AI на сервере.

`ApiClientError.kind`: input (ошибка преобразования формы), http (есть status/code/details), network (включая недоступный адрес или CORS), timeout, cancelled, invalid_response. Клиент не повторяет POST автоматически и не подменяет ошибку пустой выдачей. При 422 сопоставляйте `details[].field` с полями формы. Возвращённый сервером текст показывать как текст.

`ApiClientError.requestId` содержит серверный `X-Request-ID`, если ответ успел прийти. Добавьте его к сообщению об ошибке как «Код обращения: …», чтобы разработчик нашёл запрос в журнале. При сетевом сбое номера может не быть. Заголовки `X-Request-ID` и `X-Process-Time-Ms` доступны через CORS; успешные ответы можно проверить во вкладке Network. [Диагностика и логи](DEBUGGING.md).

Для проверки настройки фронтенда: `python -m contractor_match doctor --frontend-origin http://localhost:5173` из того же окружения, где запускается API. Команда проверяет конфигурацию на диске и в окружении, без запросов к серверу или модели.

### Типы полей формы

- Бюджет в JSON — число, не строка, ₸ и пробелы входят только в отображение. Helper принимает `'1200000'`, проверяет безопасное целое число и преобразует в 1200000.
- Длительность — число или null; пустое поле helper превращает в null, не в 0.
- Пустые language/brief — null либо отсутствуют. Не отправлять `language: ''` напрямую.
- Дата — строка input.value `YYYY-MM-DD`. Не применять `new Date(...).toISOString()` к локальной дате.
- В запросе только восемь известных полей. Helper не отправляет состояние UI, вкладки, резерв и прочие данные формы.
- Допустимые категории брать из `options.categories_by_city[city]`. После смены города очистить прежнюю категорию, если её нет в новом списке. Границы календаря брать из options.

## 4. Состояния интерфейса

| Ответ / событие | Что показать |
|---|---|
| Загрузка справочника | Loading или ошибка загрузки; поля выбора ещё не готовы |
| Отправка формы | Индикатор загрузки; предыдущие карточки не выдавать за ответ на новые условия |
| matched | 1–3 карточки в серверном порядке и response.message |
| category_absent | Категории нет в городе; не изображать ошибку сети |
| no_eligible | Категория есть, условия не выполнены; причины и alternatives |
| 422 | Ошибки полей из error.details, сохранить введённые значения |
| 500/503 | Сообщение о сбое/конфигурации; возможность повторить вручную |
| network/timeout | Состояние недоступности API, не «подрядчиков нет» |

404 и 405 тоже имеют envelope `{error:{code,message,details}}`; они обычно означают неверный путь или метод. CORS preflight — служебный OPTIONS, его ошибка может быть текстовой: UI получает её как network, а диагностика видна в DevTools.

## 5. Карточка и главная фишка

| Поле | Использование в UI |
|---|---|
| id | Стабильный ключ карточки |
| name, category, city | Заголовок и основные сведения |
| price_from_kzt | «от … ₸», без превращения в итоговую стоимость |
| explanation / why_fits | Короткое объяснение / список оснований |
| evidence_quote | Дословный фрагмент описания; автор — подрядчик |
| to_clarify, evidence_note | Что требует подтверждения |
| differences | Сравнение только с показанными кандидатами |
| synthetic, city_imputed, price_imputed | Видимые подписи происхождения данных |

Опциональные массивы читать через `?? []`. `counts.eligible_total` — все подходящие; `cards.length` — сколько показано; `counts.excluded_total` — уникальные исключённые. Не суммируйте reasons: один человек может быть одновременно занят и дороже бюджета.

Показывайте `understanding` и его notes: правила могут применить однозначный язык из текста, но стиль и отрицания не гарантируются. `ai_mode=fallback` + `ai_reason=local_requested` означает намеренный локальный режим, а не аварию. `ranking_mode` — отдельный этап; не путайте NIM ranking с AI-объяснениями.

Для каждой альтернативы покажите message, изменения from_value → to_value и eligible_count. По кнопке «Применить»:

1. Сохранить старую форму для пользовательской отмены, если это нужно дизайну.
2. Заполнить форму **всем** `alternative.request`.
3. Отправить этот request в тот же `POST /recommendations` через latest.recommend.
4. Отрисовать новый ответ. До отправки карточки относятся к старым условиям.

Не пересчитывайте количество на клиенте. Не применяйте только бюджет у предложения с двумя изменениями. `candidate_ids` служит проверке альтернативы и не заменяет ранжированные карточки нового ответа.

## Автономный веб-прототип и миграция

В отдельной ветке `codex/event-match-web-20260923` есть автономный web/dist на JavaScript. В main он не переносился этой задачей. Его matcher/planner — локальная реализация со своим расширенным поведением, а не API-клиент. При подключении дизайна переносите нужные UI-компоненты и заменяйте вызов подбора обращением к серверу.

| Поле / возможность прототипа | Текущий backend |
|---|---|
| eligible / total | counts.eligible_total / counts.category_total |
| allEligible, «За кадром», исключённые профили | Полного списка нет; только counts и reasons. Не строить его второй реализацией фильтров |
| Полное досье, все языки/часы/описание | В карточке только опубликованные поля; отдельного profile endpoint пока нет |
| Начало имени, исключение по «без конкурсов» | Не являются hard filters текущего API; пожелания честно отмечаются как непроверенные |
| Другой город как план Б | Текущие alternatives меняют только дату, бюджет, часы |
| Резерв к цене | Может быть отдельным расчётом пользователя; не фактическим тарифом и не новым серверным бюджетом без выбора пользователя |

Если новая версия дизайна требует недостающий endpoint, сначала описать контракт и добавить backend-тест, затем подключать интерфейс. Не выдумывать контакты, рейтинги, бронирование, фотографии и верхние цены из имеющихся данных.

## Проверки перед объединением

```sh
python -m unittest discover -s tests -v
python -m contractor_match.export_contract --check
node --test integration/tests/api-client.test.mjs
python -m contractor_match.demo --story
```

После изменения моделей/API: `python -m contractor_match.export_contract`, просмотр diff сгенерированных файлов, те же проверки. TypeScript типы отражают OpenAPI и не заменяют серверную валидацию; JS-клиент проверяет основные поля ответа, а не всю JSON Schema. GitHub Actions остаётся отключённым.

Минимальная ручная проверка вашей формы: 15.10 → 6 подходящих/3 карточки; 19.12 → 1; применить предложенное 17.12 → 3; флорист Астаны 15.10 за 100000 → no_eligible и составная альтернатива; ошибка 422; быстро отправить два разных запроса и убедиться, что остаётся последний результат.
