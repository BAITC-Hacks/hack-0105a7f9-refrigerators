# Состояние проекта

Обновлено 23.09.2026: номера запросов, безопасные логи и локальная команда doctor.

## Что работает

- FastAPI и CLI используют общий pipeline. Исходный CSV: 66 профилей, 13 synthetic; SHA-256 `6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d`, данные не изменялись.
- Общие hard filters в eligibility.py используются и в подборе, и при расчёте альтернатив. Окно 23.09–31.12.2026, цена «от», null часов не ограничивает длительность.
- При 0–2 подходящих — минимальные проверенные одиночные изменения даты, бюджета, часов. Если одного мало — до трёх сочетаний с минимальным числом изменённых полей и явно указанным порядком компромиссов. Каждый вариант содержит воспроизводимый request, число кандидатов и ID.
- understanding показывает ограниченный локальный разбор brief. Однозначный язык применяется, если поле language пусто; конфликт и несколько языков отмечаются. Стиль и отрицания требуют подтверждения.
- Карточки добавляют why_fits, to_clarify, differences; сравнения касаются только показанных кандидатов. Исходные поля ответа сохранены.
- TF-IDF char-tfidf-3-5-v1 — основной режим. RANKING_PROVIDER=brev включает NIM /v1/ranking; AI_PROVIDER=brev независимо включает /v1/chat/completions. Оба только по явной настройке, имена моделей обязательны.
- На внешние этапы общий deadline 6 с, ранжирование максимум 2 с. Ошибка reranker даёт tfidf с ranking_reason, ошибка объяснений — проверенные локальные цитаты с ai_reason. При пустой выдаче внешних запросов нет.
- `AGENTS.md` задаёт карту проекта и правила для Codex; `docs/FRONTEND_HANDOFF.md` — подключение существующего интерфейса и состояния экрана. Автономная веб-ветка команды не переносилась: в ней свой алгоритм, отличающийся от HTTP-контракта.
- `integration/` содержит клиент JavaScript без фреймворка, TypeScript-типы, OpenAPI и реальные примеры API. Схема, типы моделей и примеры генерируются `python -m contractor_match.export_contract`; `--check` обнаруживает расхождения. Экспорт всегда local + tfidf.
- Клиент преобразует поля формы, различает бизнес-ответ и ошибку, ограничивает ожидание, поддерживает отмену и предотвращает перезапись свежего результата старым. Он не фильтрует и не ранжирует подрядчиков.
- `requirements-lock.txt` фиксирует версии проверенного Python-окружения для воспроизведения API-схемы; диапазоны прямых зависимостей оставлены в requirements.txt. Обновление версий требует повторной проверки тестов и экспорта.
- `X-Request-ID` создаётся сервером для каждого HTTP-запроса, включая обработанные ошибки и OPTIONS. `X-Process-Time-Ms` показывает время до начала ответа. Оба заголовка открыты для браузера через CORS и описаны в OpenAPI; тело бизнес-ответа не менялось. Клиент сохраняет полученный номер в ApiClientError.requestId.
- JSON-журнал приложения в stderr связывает HTTP, подбор и fallback одним номером; показывает времена configuration/understanding/catalogue/scope/filters/alternatives/ranking/explanations, счётчики и причины. При 500 — файл/функция/строка без текста исключения, исходных строк, локальных переменных и абсолютных путей. Параллельные запросы имеют независимый контекст.
- `python -m contractor_match doctor [--json] [--frontend-origin ORIGIN]` проверяет Python, зависимости, настройки AI/CORS, свежий CSV и индекс. Работает без site-packages, не вызывает сеть и не подтверждает доступ к моделям. Ошибки дают exit 1, предупреждения — 0. Инструкция: docs/DEBUGGING.md.

## Исправлено при подготовке фронтенда

- До изменения браузерный OPTIONS preflight получал 405. Теперь CORS допускает точные настроенные origins и методы GET/POST. По умолчанию localhost/127.0.0.1 на портах 3000, 4317, 5173; конфигурация — `CORS_ALLOWED_ORIGINS`, без wildcard и передачи cookies.
- Неожиданный сбой раньше возвращал текстовый 500. Теперь 404/405/422/500/503 используют JSON-envelope `error`; обработанный 500 сохраняет CORS-заголовки и не раскрывает внутренние детали. Изначально лог содержал только класс исключения; в текущей итерации добавлены безопасные координаты сбоя и request_id.
- `.env.local` и другие `.env.*` теперь игнорируются Git вместе с `.env`; примеры разрешены. Добавлены исключения для зависимостей Node и сборки Next.js.

Preflight с origin localhost:4317 — 200; ведущий 19.12 — 1; применение предложенного 17.12 — 3; строковый бюджет — 422 с полем budget_kzt. Все ответы сохранили нужный CORS-заголовок. ## Что пока не подтверждено

- Живой OpenAI, NVIDIA Build и NIM на Brev. По решению пользователя подготовлены только код и инструкция; GPU, купоны, биллинг и Launchable не создавались/не менялись.
- Прирост качества русского семантического ранжирования и стабильность оценок на конкретной модели/GPU. Порядок при смене модели или fallback может отличаться; по одинаковым оценкам действует цена/id.
- Полное понимание произвольных пожеланий: локальные правила и сходство текста этого не гарантируют. Бронирования и живого обновления календаря нет.
- Интеграция дизайна команды в работающий сайт: frontend остаётся отдельной работой команды. В API нет полного досье, контактов и списка исключённых профилей. Клиент проверяет базовую форму ответа, а не всю JSON Schema во время выполнения.
