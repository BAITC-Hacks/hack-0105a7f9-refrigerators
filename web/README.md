# Веб-страница «рядом.»

Страница использует готовый `integration/api-client.mjs` и текущий HTTP-контракт проекта. Для локальной работы нужны два процесса из корня репозитория.

```powershell
$env:AI_PROVIDER = 'local'
$env:RANKING_PROVIDER = 'tfidf'
python -m uvicorn contractor_match.api:app --host 127.0.0.1 --port 8000 --no-access-log
```

В другом терминале:

```powershell
python -m http.server 5173 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:5173/web/`. Python-зависимости устанавливаются по корневому `README.md`. Открытие `index.html` через `file://` не поддерживается, поскольку модульный клиент и API работают через HTTP. Для другого публичного адреса API установите `window.EVENT_API_BASE_URL` до загрузки `app.js` либо измените его значение по умолчанию в `app.js`; секретные ключи сюда не добавляются. Origin страницы должен быть разрешён серверной настройкой `CORS_ALLOWED_ORIGINS`.

Форма загружает города, категории, форматы, языки и календарь из `/catalogue/options`. Рекомендации и запасные варианты приходят из `/recommendations`. Запасной вариант применяется только по нажатию кнопки: форма заполняется полным `alternative.request`, затем выполняется новый запрос. Пояснения по пожеланиям во второй вкладке относятся к уже показанным карточкам и не выдаются за дополнительных подрядчиков.

Сервер не предоставляет бронирование, контакты или отдельную выдачу кандидатов по ослабленному пожеланию. Для такой выдачи понадобится расширение серверного контракта. Проверенные изменения даты, бюджета и длительности доступны сейчас.

Для проверки окружения и origin: `python -m contractor_match doctor --frontend-origin http://127.0.0.1:5173`. При ошибке загрузки справочника или подбора страница показывает код обращения, если сервер успел вернуть X-Request-ID. По нему можно найти запрос в журнале: [диагностика](../docs/DEBUGGING.md).
